# EcuadorElectricGrid

`EcuadorElectricGrid` is a PyPSA-based teaching and research project for
reconstructing, simulating, and validating Ecuador's 2022 interconnected power
system, then using the validated model as the foundation for future-grid studies.

## Current status

The repository is in Phase 2 of a full refactor. It contains valuable working
2017/2018 studies, a partially completed 2022 notebook chain, manually prepared
Master Plan tables, candidate network artifacts, and solved experiments. It does
**not** yet contain a reproducible, scientifically validated 2022 baseline.

The immediate target is a complete 2022 annual simulation whose energy supply by
carrier agrees with authoritative Ecuador 2022 statistics within the agreed 5%
tolerance. Future scenarios—including any nuclear sensitivity—are deliberately
deferred until that baseline passes.

## Intended student workflow

The supported workflow will be a sequence of documented notebooks backed by
reusable functions in `src/`:

1. preflight and external-data retrieval;
2. demand preparation and validation;
3. existing-generation preparation and renewable/hydro profiles;
4. transmission-network repair and validation;
5. 2022 model assembly and short smoke run;
6. full-year 2022 solve and statistical validation;
7. Master Plan expansion-data preparation;
8. student-authored future scenarios and reporting.

Every notebook will state its inputs, outputs, sources, assumptions, and
validation criteria. Validation plots shown in notebooks will also be saved for
the phase technical reports.

## Environment policy

Development uses the existing Conda environment `pypsa-earth-ec`. The refactor
must not create a repository-specific or temporary virtual environment. Activate
the existing environment through the user's Conda installation:

```powershell
conda activate pypsa-earth-ec
python --version
```

If `conda` is unavailable in the current shell, initialize it using the user's
existing Conda installation rather than recording an installation location in
the repository. Do not run the scientific notebooks with the system Python.

## Large external data

The required upstream NetCDF inputs—`base.nc`, `solar.nc`, and `onwind.nc`—are
published in a versioned Zenodo record. Before the first workflow notebook runs,
a preflight stage will check them, download only missing files, verify checksums,
and place them at documented repository-relative paths.

The full ERA5/atlite cutout is not required by the supported notebooks; it belongs
to upstream renewable-profile regeneration in `EcuadorElectricGridData`.
`ec_network_2022.nc` and `network_base_filled.nc` are generated by this
repository's cleaning and assembly notebooks and are not raw inputs. Their current
unvalidated instances will not be published as source artifacts.

The required upstream files are published in the versioned Zenodo record
[`10.5281/zenodo.23392049`](https://doi.org/10.5281/zenodo.23392049). Phase 1
verified the three direct downloads against the observed sizes and SHA-256
checksums. See the
[data contract](docs/DATA_AND_ARTIFACTS.md) and
[Zenodo handoff](docs/ZENODO_HANDOFF.md).

## Mandatory preflight

Before running scientific processing, activate `pypsa-earth-ec` and run:

```powershell
python -m src.preflight --stage 00_preflight
```

The command validates the environment, obtains missing published artifacts,
checks size/SHA-256/NetCDF structure, and fails once with a complete report if
anything remains unresolved. See the [preflight guide](docs/PREFLIGHT.md).
