## Do not include

- the full ERA5/atlite cutout: it is not a supported workflow dependency;
- `ec_network_2022.nc`: it is generated by topology cleaning;
- `network_base_filled.nc`: it is generated by model assembly and is not yet
  validated;
- solved networks or alternate nuclear/scenario networks.

## Record metadata follow-up

The record already provides its title, creator, version, publication date, and
license. Its metadata should continue to preserve or add, where available:

- title describing Ecuador, PyPSA-Earth, the base network, and 2013 renewable
  profiles;
- creators and affiliations;
- the exact companion-project revision and generation workflow;
- geographic/model boundary;
- weather year and why it differs from the 2022 demand/generation study year;
- software/workflow versions used to generate the files;
- license and attribution requirements inherited from all upstream sources;
- links to the companion data repository and this model repository;
- a statement that these are upstream inputs, not a validated 2022 solved model.

The version DOI, direct file URLs, license, sizes, and checksums are now known.
Phase 2 will place them in the executable repository manifest.

## Retrieval test protocol for Phase 2

The test must protect the only local copies:

1. verify the current files against the recorded hashes;
2. move them to a clearly named backup location outside their authoritative
   destinations;
3. run the preflight through the approved environment;
4. confirm all three files are downloaded, atomically installed, and hash-identical;
5. run preflight again to prove valid files are reused without downloading;
6. corrupt or truncate a disposable copy and confirm preflight rejects it;
7. retain logs and restore the verified backups if any retrieval test fails.

Temporary absence from the authoritative paths is appropriate. Deleting the only
verified copies before the download test succeeds is not.
